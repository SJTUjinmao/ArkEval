# ArkTS 修复工作流

## 目的

本文档记录当前 HarmonyOS / ArkTS 任务的命令行修复流程。目标是把环境初始化、base 失败采集、智能体修复和最终验证固定到同一条可复现路径上。

## 标准流程

1. 将目标仓库恢复到 base 状态。
2. 初始化验证环境。
3. 先运行一次提供的构建或测试工具，采集真实失败输出。
4. 将 issue 描述、失败输出和已知缺陷文件路径交给修复智能体。
5. 每次修复尝试后，重新运行同一套工具。
6. 如果所有检查通过，则提交结果。
7. 如果检查仍失败，则带着新失败输出回到第 4 步，直到达到步数预算或智能体提前提交。

## 步骤 1：环境初始化

环境初始化不只是加载 `.env`，还必须把仓库准备到纯命令行 hvigor 可运行的状态。

必需初始化动作：

1. 加载 `command_line_tools_test/.env`。
2. 导出必需的工具路径和环境变量，例如：
   - `DEVECO_PATH`
   - `DEVECO_SDK_HOME`
   - `OHOS_BASE_SDK_HOME`
   - `OHOS_SDK_HOME`
   - `JAVA_HOME`
   - `NODE_HOME`
   - 需要设备命令时使用 `HDC_PATH`
3. 当 `<repo_root>/local.properties` 不存在，或其中的 `sdk.dir` 已过期时，自动创建或重写它。

### local.properties 规则

在 DevEco Studio 里，`local.properties` 会自动生成。在命令行工作流中，这个文件必须由我们的工具创建。

目标文件：

`<repo_root>/local.properties`

必需内容：

```properties
# This file is automatically generated by DevEco Studio.
# Do not modify this file -- YOUR CHANGES WILL BE ERASED!
#
# This file should *NOT* be checked into Version Control Systems,
# as it contains information specific to your local configuration.
#
# For customization when using a Version Control System, please read the header note.
sdk.dir=C:/Users/xb/AppData/Local/OpenHarmony/Sdk
```

事实来源：

- `command_line_tools_test/.env`
- 重点是 `DEVECO_SDK_HOME=C:\path\to\OpenHarmony\Sdk`

规范化规则：

- `sdk.dir` 使用正斜杠形式，例如 `C:/Users/xb/AppData/Local/OpenHarmony/Sdk`

原因：

- 如果没有 `local.properties`，直接执行 `hvigorw.bat` 可能失败：
  `Unable to find 'sdk.dir' in 'local.properties' or 'OHOS_BASE_SDK_HOME'`

## 步骤 2：采集 base 失败

在让智能体修代码前，应先运行一次提供的工具，并保留真实失败输出。

推荐工具：

- `command_line_tools_test/tools/build_app.py`
- `command_line_tools_test/tools/run_local_tests.py`

base 失败输出是修复上下文的一部分，应和以下内容一起交给智能体：

- issue 描述
- 已知缺陷文件
- 构建或测试日志

## 步骤 3：智能体修复

智能体应基于给定 issue 上下文和缺陷文件范围修复，不应另起一套工具链路径，也不应在工具已经提供路径时手动搜索 hvigor、node 或 SDK。

推荐规则：

1. 阅读 issue 描述。
2. 阅读已知缺陷文件。
3. 使用提供的构建或测试工具验证。
4. 保持修改最小且聚焦。

## 步骤 4：验证循环

每次修复尝试后：

1. 再次运行提供的验证工具。
2. 如果所有检查通过，则提交。
3. 如果检查失败，把新失败输出送回下一轮修复。
4. 仅在以下情况停止：
   - 所有检查通过
   - 达到步数上限
   - 智能体明确提交

## 当前工具契约

命令行工具现在把 `local.properties` 生成视为 hvigor 运行前初始化的一部分。

当前覆盖：

- `tools/build_app.py`
- `tools/run_local_tests.py`

两个脚本都会：

1. 加载 `.env`
2. 解析 SDK 根目录
3. 创建或刷新 `local.properties`
4. 继续执行 hvigor 相关工作

## 实用说明

- `ohpm install` 和 `local.properties` 解决的是不同问题。
- `ohpm install` 准备项目依赖。
- `local.properties` 给 hvigor 一个稳定的 SDK 位置。
- 两者都是可靠命令行修复循环所必需的。

## 简版流程

可以把下面内容作为简洁工作流引用：

1. 将仓库恢复到 base 状态。
2. 初始化环境。
3. 根据 `.env` 中的 `DEVECO_SDK_HOME` 自动创建 `local.properties`。
4. 运行 base 构建或测试工具并采集失败。
5. 将 issue 描述、失败日志和缺陷文件交给智能体。
6. 修复。
7. 重新运行工具。
8. 通过则提交；失败则继续，直到达到步数上限。
